# ETrade local read-only proxy — from-scratch Rust CLI

A loopback-only HTTPS reverse proxy that structurally isolates the ETrade read surface: it admits only `GET` under `/etrade-api/v1/accounts`, signs each proxied call with OAuth 1.0a using an in-memory access token obtained via a fresh three-leg flow at every startup, and relays a bounded, header-filtered response. The implementation follows the mandated functional-core / imperative-shell split: a pure, deterministic core (admission, OAuth signing, query handling, config validation, status, fingerprint) with injected clock/nonce, behind a thin async shell (axum/reqwest/rustls/rcgen, stdin/stdout, env). Errors are typed per module via `thiserror`, with `anyhow` only at `main`.

Watch for: nothing blocking. The ETrade endpoint paths, the authorize URL, and `oauth_callback=oob` are documented first-run assumptions that AC-13 (wiremock-only) cannot verify — isolated as single-source constants with diagnostics (confirmed). The 503-while-Pending window is impossible in production because `main` only serves after the flow completes, but the serve seam allows a Pending state for tests (confirmed, by design).

**Verdict**: APPROVED

## High-level view

The central security invariant — GET-only, prefix-only forwarding — lives in one total pure function, `core::admission::admit`, enforced verb-first so a `POST` to `/etrade-api/v1/accounts/{id}/orders` is rejected before the path is even examined. The shell's single axum fallback handler routes every request through `admit`, so there is no method-pre-routed path that could bypass it. Property tests cover totality, non-GET-never-forwards, out-of-prefix-never-forwards, and in-prefix-maps-with-query; an end-to-end test confirms a POST produces 405 with zero upstream hits.

The OAuth signing domain is modeled around the three legs as distinct typed inputs (`SigningInput::{RequestToken, AccessToken, Resource}`), each carrying exactly the fields its leg admits, with the token secret traveling inside the variant. This makes the classic failure (a request-token leg emitting `oauth_token=""`) unrepresentable rather than merely avoided. Base string and `Authorization` header both derive from the same `OauthParams::as_pairs()`, so they cannot diverge; property tests assert the parsed-back header multiset equals `as_pairs()` across all three legs.

Non-determinism is injected through `Clock`/`NonceSource` generator traits. The shell draws a fresh `(nonce, timestamp)` immediately before signing each leg and each proxied request; the pure core only ever receives pinned values. Freshness is pinned by tests at the shell (sequential proxied GETs and the two OAuth legs carry distinct `oauth_nonce`) because the wiremock upstream does not validate nonces.

The bind address is a code constant (`127.0.0.1`); only the port is configurable, proptest-checked loopback for every `u16`. Credentials are `secrecy::SecretString` with a single source-level `expose_secret()` site; non-secret tokens carry redacting `Debug`. The access token exists only inside the `Authorized` typestate held behind `Arc<RwLock<AuthPhase>>`; no code path writes token material to disk. The upstream relay buffers the body under a hard 8 MiB cap and copies only a whitelisted set of response headers, dropping `Content-Length` and hop-by-hop headers.

The core tree references none of tokio/axum/reqwest/rustls/std::env/std::io (grep-confirmed; only doc comments mention them), so the litmus test from the steering doc holds. The gate is green: `cargo build`, `cargo clippy --all-targets --all-features -- -D warnings` (zero warnings), and `cargo test` (110 passing: 101 unit/proptest + 9 integration) all pass, independently reproduced.

### Verb-first admission as the single enforced invariant

`admit(method, path_and_query)` is total and verb-first: a non-`GET` returns `Reject(MethodNotGet)` before the path is parsed, so the shared-prefix write endpoint (`POST .../orders`) cannot slip through a path allow-list. Prefix matching guards segment boundaries (`/etrade-api/v1/accountsX` does not match) using only `strip_prefix`/`split_once`, never panicking indexing. The shell maps the two reject reasons to exactly one status each (405/404), giving the acceptance criteria unambiguous targets.

The one place this could be undermined is routing: if the shell pre-matched methods or paths at the axum layer, a bypass could exist. It does not — `router` registers a single `.fallback(handle)` and `handle` converts to core types and calls `admit`. The end-to-end `post_under_prefix_is_405_and_never_forwarded` test mounts a catch-all wiremock mock and asserts zero hits, proving the structural guarantee past the pure-function level.

### Three-leg OAuth modeled as distinct typed domains

Rather than one signing function over an optional token, the three legs are separate `SigningInput` variants. `RequestToken` has no token field at all, so `oauth_token` is structurally absent (not empty) on leg 1; `AccessToken` and `Resource` each carry their public token plus the matching secret. `sign_leg` is the single enforcing call site: it matches the variant to pick the token secret, so pairing the wrong secret with a leg is unrepresentable.

```
oauth_params(SigningInput, nonce, ts) → OauthParams   (no signature; token absent on leg 1)
as_pairs() ++ query_params → signature_base_string → sign_hmac_sha1 → authorization_header
```

Both the base string and the header read the same `as_pairs()`, and `signature_base_string` sorts a copy of the already-encoded pairs — so the signed set and the rendered header cannot diverge. The `header_agrees_with_as_pairs` proptest confirms this across all three legs for arbitrary values, and asserts leg 1 emits zero `oauth_token` while the other two emit exactly one. The HMAC implementation is checked against the RFC 2202 Jefe test vector.

### Query handling keeps signed and sent sets byte-identical

`split_query` decodes each name/value, drops any incoming `oauth_*` parameter (so a client cannot inject or shadow a protocol parameter), and preserves duplicates as an ordered multiset. Non-UTF-8 percent escapes are kept raw rather than lossily substituted with U+FFFD, then re-encoded identically on both the base string and the wire query — a deliberate double-encoding trade-off that keeps the signed and sent sets equal (so no 401), documented and property-tested (`non_utf8_escapes_total_and_consistent`, `signed_set_equals_wire_set`). The outbound URL is rebuilt from the same signed pairs via `wire_query`, never from the raw client query.

### Injected non-determinism and freshness

`Clock`/`NonceSource` are generator traits; the real nonce source is a 160-bit CSPRNG hex, the real clock is `SystemTime` with the one sanctioned `expect` (pre-1970 clock is an unrecoverable startup condition, documented). The shell draws a fresh pair immediately before each signing call. Because wiremock does not enforce nonce uniqueness, freshness is pinned explicitly: `sequential_gets_carry_distinct_nonces` (proxy) and `three_leg_flow_signs_each_leg_with_distinct_nonces` (OAuth) assert distinct `oauth_nonce` in recorded upstream headers via a counter-backed source.

### Loopback bind, TLS, and credential handling

`bind_addr` constructs `SocketAddr` from `Ipv4Addr::LOCALHOST` and the port; nothing derives the IP from input, config, or env, and `bind_addr_always_loopback` proptests it over every `u16`. TLS is an ephemeral in-memory rcgen cert; the SHA-256 fingerprint is computed by the pure core and printed, no file written. The rustls provider is pinned explicitly to `aws_lc_rs` via `builder_with_provider` because reqwest's rustls-tls also pulls a provider into the graph, which would otherwise make the process default ambiguous — a real correctness fix, not boilerplate.

Credentials are `SecretString` (redacting `Debug`, no `Display`, zeroize on drop) with the sole `expose_secret()` call inside `signing_key`, where the exposed `&str` is folded into the HMAC key and never escapes. Non-secret tokens carry a hand-written truncating `Debug` with char-boundary-safe slicing (tested against multibyte input). The access token lives only inside the `Authorized` typestate; `authorized_handle` clones the `Arc` out under a short read guard so the lock is never held across an `.await`.

### Bounded relay and failure modes

`read_bounded` checks `buf.len() + chunk.len() > cap` before appending, so an over-cap or malicious upstream cannot drive unbounded allocation; exceeding the 8 MiB cap maps to `UpstreamTooLarge` → 502, a transport error to `Upstream` → 502, and a not-yet-authorized state to `NotReady` → 503. The body is fully buffered before any status/headers are written, so there is no mid-stream failure window. Only the whitelisted response headers are copied; `Content-Length` and hop-by-hop headers are dropped, verified by the header-filter integration assertion and the relay unit tests.

### Error typing and the main boundary

Each module exposes a `#[non_exhaustive]` `thiserror` enum with `#[from]` conversions; `anyhow` appears only in `main` (grep-confirmed — the shell/error.rs mention is a doc comment). Config errors name the variable, never the value, and are surfaced before any socket bind. The OAuth leg errors name the endpoint constant and, on the request-token leg, append a hint that `oauth_callback=oob` is an unverified assumption worth checking on a 401 — making a wrong first-run assumption diagnosable rather than opaque.
